## Как читать

Репозиторий — просто набор `.md`-файлов со ссылками между собой, без привязки
к конкретному инструменту:

- **Obsidian** — основной способ автора. Настройки вида (граф, плагины) лежат
  в `.obsidian/` и закоммичены в репозиторий, кроме `workspace*.json`
  (локальная раскладка окна конкретного устройства, в `.gitignore`).
  Открывается как обычный vault.
- **VS Code** — родной предпросмотр Markdown и переходы по ссылкам работают
  из коробки, плагин Obsidian не нужен.
- **Веб на GitHub** — репозиторий читается прямо в интерфейсе gh.com, ссылки
  между файлами кликабельны.

### Быстро открыть на телефоне (Obsidian Mobile)

1. Установить [Obsidian](https://obsidian.md) и плагин **Git** (Community
   plugins → Git) — либо синхронизировать через Obsidian Sync/iCloud/Syncthing,
   если git-клиент на телефоне неудобен.
2. В плагине Git выбрать «Clone an existing remote repo» и указать URL этого
   репозитория.
3. Открыть склонированную папку как vault — настройки из `.obsidian/`
   подтянутся автоматически.

## Как этим пользоваться

Читать по порядку внутри `index.md` раздела — темы выстроены от основ к
продвинутым, и поздние опираются на ранние. Внизу и вверху каждой страницы —
ссылки на соседние темы.

Раздел «Основы программирования» языконезависимый: там теория и формулировки,
а нюансы конкретного языка вынесены ссылками **В Python:** / **В SQL:** в конце
соответствующего вопроса.

Каждая тема — это набор вопросов в той формулировке, в которой их задаёт
интервьюер. Ответ устроен слоями, чтобы страница работала на разном уровне
подготовки:

- **Коротко** — модель устного ответа на одну-две фразы. Если готовитесь
  быстро — читайте только эти строки и переходите к следующему вопросу.
- Разбор — развёрнутое объяснение с нуля, термины вводятся до использования.
- Пример — рабочий код с показанным выводом.
- **Подвох** — чем интервьюер попробует сбить с толку и что ответить.
- **Глубже** — деталь реализации или edge case; то, ради чего шпаргалку
  открывает человек, который тему уже знает.

## Проверки

Примеры проверены на CPython 3.14. Две проверки перед коммитом:

```bash
bash scripts/check-links.sh
```

```bash
python scripts/check-text.py
```

Первая ловит битые ссылки и файлы, выпавшие из навигационной цепочки; вторая —
опечатки, смешанную раскладку внутри слова и посторонние символы.

Новая тема — отдельный `.md`-файл со ссылками на соседние темы вверху и внизу
страницы; при добавлении нужно перешить всю цепочку и обновить `index.md`
раздела.
