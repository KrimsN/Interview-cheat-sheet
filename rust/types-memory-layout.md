## Какие в Rust скалярные типы и почему нет неявных преобразований?

**Коротко.** Целые `i8…i128`/`u8…u128`, машинно-зависимые `isize`/`usize`,
плавающие `f32`/`f64`, `bool` и `char` (скалярное значение Unicode, 4 байта).
Неявных числовых преобразований нет вообще: либо `as` (усечение без проверки),
либо `TryFrom` (проверяемое, возвращает `Result`).

```rust
fn main() {
    let a: i64 = 300;
    let b = a as u8;                  // 44 — молча усекли по модулю 256
    let c = u8::try_from(a);          // Err(TryFromIntError)
    println!("{b} {c:?}");            // 44 Err(TryFromIntError(()))

    let x: u32 = 5;
    let y: u64 = 7;
    // let z = x + y;                 // ошибка: mismatched types
    let z = u64::from(x) + y;         // явное расширение без потерь
    println!("{z}");                  // 12
}
```

Правило выбора: `usize` — для индексов и длин (совпадает с размером
указателя), `u32`/`i64` — для данных предметной области, `as` — только когда
усечение осознанно (маски, работа с байтами), во всех остальных случаях
`From`/`TryFrom`.

**Подвох.** `char` — это не байт и не UTF-8-последовательность, а именно
кодовая точка размером 4 байта. `'я' as u32` даёт 1103, а в строке этот же
символ занимает 2 байта UTF-8. Отсюда все особенности работы со
[строками](strings.md).

## Что происходит при переполнении целого?

**Коротко.** Это не неопределённое поведение, а два определённых режима: в
debug-сборке — паника «attempt to add with overflow», в release —
обёртывание по модулю (two's complement wrapping). Режим управляется флагом
`overflow-checks`.

```rust
fn main() {
    let x: u8 = 250;
    println!("{:?}", x.checked_add(10));      // None
    println!("{}", x.saturating_add(10));     // 255
    println!("{}", x.wrapping_add(10));       // 4
    println!("{:?}", x.overflowing_add(10));  // (4, true)
}
```

Явные варианты — правильный ответ на «как считать безопасно»: `checked_*`
для валидации, `saturating_*` для счётчиков и метрик, `wrapping_*` для хешей
и криптографии, `overflowing_*` когда нужен и результат, и флаг.

**Подвох.** Разное поведение debug и release означает, что баг переполнения
может не воспроизвестись в тестовой сборке и «выстрелить» в проде наоборот —
или, что чаще, паника в debug укажет на ошибку, которую release тихо
проглотит. Для боевых сборок, где важна диагностика, включают
`overflow-checks = true` в профиле release.

## Как в памяти лежат структуры и перечисления?

**Коротко.** Раскладка по умолчанию (`repr(Rust)`) **не определена**:
компилятор вправе переупорядочить поля ради упаковки и выравнивания.
Стабильная раскладка задаётся атрибутами `#[repr(C)]`, `#[repr(u8)]`,
`#[repr(transparent)]`, `#[repr(packed)]`.

```rust
use std::mem::{size_of, align_of};

#[repr(C)]
struct CStyle { a: u8, b: u32, c: u8 }  // порядок как в объявлении + паддинг

struct RustStyle { a: u8, b: u32, c: u8 } // компилятор переставит поля

fn main() {
    println!("{} {}", size_of::<CStyle>(), align_of::<CStyle>());   // 12 4
    println!("{}", size_of::<RustStyle>());                          // 8
}
```

`#[repr(C)]` нужен для [FFI](unsafe-ffi.md) и любых данных, которые читает
чужой код; `#[repr(transparent)]` — для newtype-обёрток, гарантирует ту же
раскладку, что у внутреннего типа.

Перечисление — размеченное объединение (tagged union): размер равен тегу плюс
наибольший вариант с учётом выравнивания. Поэтому один «толстый» вариант
раздувает все значения типа, и его боксируют:

```rust
enum Message {
    Ping,
    Payload(Box<[u8; 1024]>), // без Box каждый Message весил бы > 1 КиБ
}
```

Именно на это ругается линт `clippy::large_enum_variant`.

## Что такое niche-оптимизация и почему `Option<&T>` не занимает лишней памяти?

**Коротко.** Если у типа есть невозможные битовые представления («ниши»),
компилятор кодирует ими вариант перечисления вместо отдельного тега. У ссылки
запрещён нулевой адрес — им и кодируется `None`.

```rust
use std::mem::size_of;
use std::num::NonZeroU32;

fn main() {
    println!("{}", size_of::<&u8>());              // 8
    println!("{}", size_of::<Option<&u8>>());      // 8 — ниша, не 16
    println!("{}", size_of::<Option<Box<u8>>>());  // 8
    println!("{}", size_of::<NonZeroU32>());       // 4
    println!("{}", size_of::<Option<NonZeroU32>>()); // 4
    println!("{}", size_of::<Option<u32>>());      // 8 — ниши нет, нужен тег
}
```

Практический вывод: `Option<Box<T>>` в FFI — это ровно «указатель, возможно
нулевой», и `Option<&T>` можно передавать в C-функцию, ожидающую
`T*`. А `Option<u32>` вдвое больше `u32`, потому что все 2³² битовых
комбинаций заняты.

**Глубже.** Ниши есть и у `bool` (валидны только 0 и 1), у `char` (не все
значения — валидные кодовые точки), у `NonNull`. Поэтому
`Option<Option<bool>>` занимает всё тот же 1 байт. Посмотреть реальные
размеры целиком можно nightly-флагом `-Zprint-type-sizes`.

## Что такое `Sized`, DST и широкие указатели?

**Коротко.** `Sized` — типы, размер которых известен на этапе компиляции; у
каждого параметра типа есть неявная граница `T: Sized`. Типы с неизвестным
размером (DST — dynamically sized types) — `[T]`, `str`, `dyn Trait` —
существуют только за указателем, и такой указатель «широкий»: он несёт
дополнительное слово метаданных.

```rust
use std::mem::size_of;

fn main() {
    println!("{}", size_of::<&u8>());        // 8  — обычный указатель
    println!("{}", size_of::<&[u8]>());      // 16 — адрес + длина
    println!("{}", size_of::<&str>());       // 16 — адрес + длина в байтах
    println!("{}", size_of::<&dyn std::fmt::Debug>()); // 16 — адрес + vtable
}
```

Отсюда сразу два следствия, которые любят спрашивать:

- трейт-объект нельзя вернуть по значению — `fn f() -> dyn Trait` не
  компилируется, нужен `Box<dyn Trait>` или `impl Trait`;
- функция, которая должна принимать и `str`, и `[T]`, объявляет
  `T: ?Sized`, снимая неявную границу:

```rust
fn print_len<T: ?Sized + AsRef<str>>(s: &T) {
    println!("{}", s.as_ref().len());
}
```

**Подвох.** `?Sized` — это не «может быть не Sized и с этим ничего нельзя
делать», а расширение множества допустимых типов. Ограничение при этом
жёсткое: значение DST нельзя положить на стек, передать по значению или
вернуть — только за `&`, `Box`, `Rc`, `Arc`.

## Что даёт newtype и чем он отличается от псевдонима типа?

**Коротко.** Newtype — `struct UserId(u64)` — это **новый тип** без затрат в
рантайме: система типов их различает, машинный код тот же. Псевдоним —
`type UserId = u64;` — просто сокращение, никаких новых проверок.

```rust
struct UserId(u64);
struct OrderId(u64);

fn load_user(id: UserId) -> String { format!("user {}", id.0) }

type Meters = f64; // всего лишь имя, компилятор его «раскрывает»

fn main() {
    let u = UserId(7);
    // load_user(OrderId(7));  // ошибка: mismatched types — то, ради чего это делается
    println!("{}", load_user(u)); // user 7
}
```

Newtype нужен ещё и для обхода orphan rule: реализовать чужой трейт для
чужого типа нельзя, а для своей обёртки — можно (см. [трейты](traits.md)).

Псевдоним удобен, чтобы сократить длинные обобщённые типы, — классика:

```rust
type Result<T> = std::result::Result<T, MyError>;
```

**Глубже.** Newtype — основа приёма «сделать некорректные состояния
непредставимыми»: если конструктор `Email::parse(&str) -> Result<Email, _>`
единственный способ получить `Email`, то любая функция, принимающая `Email`,
уже не обязана валидировать вход. Подробнее — в
[идиомах и проектировании API](idioms-api-design.md).
