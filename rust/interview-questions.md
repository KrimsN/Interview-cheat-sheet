# Типовые вопросы и задачи

[← Идиомы и проектирование API](idioms-api-design.md) · [🏠 Домой](../README.md)

---

Чек-лист-повторение по всему разделу. Если по каждому пункту получается за
минуту вслух воспроизвести ответ — база закрыта. Полный разбор — в теме по
ссылке; здесь подсказка на две-три строки для самопроверки.

## Владение, заимствование, типы

1. **Сформулируйте три правила владения.** → [владение](ownership.md)
   У каждого значения ровно один владелец; владелец один в каждый момент
   времени; при выходе владельца из области видимости значение уничтожается
   (вызывается `Drop`).

2. **Чем `Copy` отличается от `Clone` и почему тип с `Drop` не может быть
   `Copy`?** → [владение](ownership.md)
   `Copy` — неявная побитовая копия, `Clone` — явная и потенциально дорогая.
   Будь тип с `Drop` копируемым, деструктор отработал бы для каждой копии и
   ресурс освободился бы дважды.

3. **Правило заимствования.** → [заимствование](borrowing-lifetimes.md)
   Либо сколько угодно `&T`, либо ровно одна `&mut T`. «Shared XOR mutable» —
   отсюда статическое отсутствие гонок данных.

4. **Что такое NLL?** → [заимствование](borrowing-lifetimes.md)
   Заимствование живёт до последнего использования ссылки, а не до конца
   блока. Благодаря этому компилируется код, где `push` идёт после последнего
   чтения ранее взятой ссылки.

5. **Что означает `T: 'static`?** → [заимствование](borrowing-lifetimes.md)
   Не «живёт вечно», а «не содержит заимствований короче программы».
   `String` этому удовлетворяет, `&local` — нет. Эту границу требуют
   `thread::spawn` и `tokio::spawn`.

6. **Когда нужны явные аннотации времён жизни?** →
   [заимствование](borrowing-lifetimes.md)
   Когда правила elision не дают однозначного ответа: несколько входных
   ссылок и возвращаемая ссылка, структуры со ссылочными полями.

7. **Чем `&str` отличается от `String`, `&[T]` от `Vec<T>`?** →
   [строки](strings.md), [коллекции](collections.md)
   Первые — заимствованные срезы (адрес + длина), вторые — владеющие буферы в
   куче. Правило API: принимать срез, возвращать владеющий тип.

8. **Что такое DST и почему `dyn Trait` нельзя вернуть по значению?** →
   [типы](types-memory-layout.md)
   У `[T]`, `str`, `dyn Trait` размер неизвестен на этапе компиляции, они
   живут только за указателем. Возврат по значению требует `Sized`, поэтому
   нужен `Box<dyn Trait>` или `impl Trait`.

9. **Почему `Option<Box<T>>` занимает столько же, сколько `Box<T>`?** →
   [типы](types-memory-layout.md)
   Niche-оптимизация: нулевой адрес — невозможное значение для `Box`, им и
   кодируется `None`. С `Option<u32>` так не выйдет — свободных битовых
   комбинаций нет.

10. **Что происходит при целочисленном переполнении?** →
    [типы](types-memory-layout.md)
    Debug — паника, release — обёртывание. Это два определённых режима, не
    UB. Явные варианты: `checked_*`, `saturating_*`, `wrapping_*`.

## Абстракции

11. **Чем трейт отличается от интерфейса Java и от неявных интерфейсов Go?**
    → [трейты](traits.md)
    Реализация явная (`impl Trait for Type`), полей нет, наследования
    реализации нет. В Go интерфейс удовлетворяется структурно, в Rust —
    намеренно.

12. **Что такое orphan rule?** → [трейты](traits.md)
    Реализовать трейт можно, если ваш крейт владеет либо трейтом, либо типом.
    Гарантирует единственность реализации; обходится newtype-обёрткой.

13. **Когда ассоциированный тип, а когда параметр типа?** →
    [трейты](traits.md)
    Ассоциированный — когда реализация на тип ровно одна (`Iterator::Item`);
    параметр — когда их много (`From<T>`).

14. **Статическая диспетчеризация против `dyn`.** →
    [дженерики](generics-monomorphization.md)
    Дженерики: мономорфизация, инлайнинг, нулевая цена в рантайме, но
    раздувание кода и время сборки. `dyn`: один экземпляр кода, гетерогенные
    коллекции, косвенный вызов без инлайнинга.

15. **Что делает трейт непригодным для трейт-объекта?** →
    [трейты](traits.md)
    Обобщённые методы, `Self` в возвращаемом типе, методы без `self`. Обход —
    `where Self: Sized` на проблемном методе.

16. **Чем `impl Trait` в аргументе отличается от `impl Trait` в возврате?** →
    [дженерики](generics-monomorphization.md)
    В аргументе — сахар для обобщённого параметра. В возврате — один
    конкретный скрытый тип, поэтому две ветки не могут вернуть разные
    замыкания без `Box<dyn ...>`.

17. **Чем `Fn`, `FnMut` и `FnOnce` отличаются?** →
    [замыкания](closures-iterators.md)
    По тому, как замыкание получает `self`: `&self` (только читает),
    `&mut self` (изменяет), `self` (потребляет, вызывается один раз). Трейт
    выбирает компилятор по телу.

18. **Почему цепочка итераторов не медленнее цикла?** →
    [замыкания](closures-iterators.md),
    [производительность](performance.md)
    Адаптеры мономорфизируются и инлайнятся в один цикл, а итерация по срезу
    ещё и снимает проверку границ. Проверять всё равно бенчмарком.

19. **Чем `Rc` отличается от `Arc` и что даёт `RefCell`?** →
    [умные указатели](smart-pointers.md)
    `Rc` — неатомарный счётчик, только один поток; `Arc` — атомарный.
    `RefCell` переносит проверку заимствования в рантайм, нарушение — паника.

## Ошибки

20. **`Result` против исключений.** → [ошибки](error-handling.md)
    Ошибка видна в сигнатуре, её нельзя молча проигнорировать, нет невидимых
    путей выхода. Цена — многословность, которую снимает `?`.

21. **Что именно делает `?`** → [ошибки](error-handling.md)
    Разворачивает `Ok`/`Some` либо делает ранний возврат, применяя `From` к
    типу ошибки. Работает в функциях, возвращающих `Result`/`Option`,
    включая `main`.

22. **Когда `panic!` уместна?** → [ошибки](error-handling.md)
    Нарушен инвариант, ошибка программиста, невозможное состояние. Ввод
    пользователя, сеть, файлы — всегда `Result`.

23. **`thiserror` или `anyhow`?** → [ошибки](error-handling.md)
    Библиотека — конкретный enum (`thiserror`), чтобы вызывающий мог
    разобрать причину. Приложение — стёртый тип с контекстом (`anyhow`).

24. **Что будет при панике в потоке, в задаче tokio, за границей FFI?** →
    [ошибки](error-handling.md), [unsafe](unsafe-ffi.md)
    Поток: умирает только он, `join()` вернёт `Err`. Задача: `JoinError`
    с `is_panic()`, рантайм жив. FFI: раскрутка через кадр C — UB, нужен
    `catch_unwind`.

## Конкурентность

25. **`Send` и `Sync` — в чём разница, приведите пример типа с одним и без
    другого.** → [потоки](threads-send-sync.md)
    `Send` — можно переместить в другой поток, `Sync` — можно делить `&T`.
    `RefCell` — `Send`, но не `Sync`; `MutexGuard` — `Sync`, но не `Send`.

26. **Почему `Rc` нельзя отправить в поток?** →
    [потоки](threads-send-sync.md)
    Счётчик ссылок неатомарен: два потока могут одновременно его изменить,
    и объект освободится раньше времени либо потечёт.

27. **Что гарантирует «fearless concurrency» и чего не гарантирует?** →
    [потоки](threads-send-sync.md)
    Гарантирует отсутствие гонок данных. Не гарантирует отсутствия дедлоков,
    логических состояний гонки и утечек.

28. **Зачем `Arc<Mutex<T>>` — оба слоя?** →
    [синхронизация](sync-primitives.md)
    `Arc` даёт разделяемое владение, `Mutex` — взаимное исключение. Это
    ортогональные задачи.

29. **Что такое отравление мьютекса?** →
    [синхронизация](sync-primitives.md)
    Паника с захваченной блокировкой помечает мьютекс; последующий `lock()`
    вернёт `Err`. Данные достаются через `into_inner()`.

30. **`Relaxed` против `SeqCst`.** → [синхронизация](sync-primitives.md)
    `Relaxed` даёт только атомарность операции и годится для счётчиков.
    `SeqCst` устанавливает глобальный порядок и дороже. Ошибка проявится на
    ARM, а не на x86.

31. **Чем async-задача отличается от потока?** → [async](async-await.md)
    Задача — состояние в userspace (сотни байт), поток — стек ~2 МБ и
    планировщик ядра. Async выигрывает на тысячах ожиданий, не ускоряет
    вычисления.

32. **Почему нельзя блокировать внутри `async fn`?** →
    [async](async-await.md)
    Задача занимает рабочий поток между точками `.await`; блокирующий вызов
    останавливает все задачи на этом потоке. Решение — `spawn_blocking`.

33. **Что такое cancel safety?** → [async](async-await.md)
    Футура отменяется сбрасыванием, поэтому в цикле `select!` можно
    использовать только операции, которые безопасно прервать на середине.

34. **Зачем нужен `Pin`?** → [async](async-await.md)
    Сгенерированная футура может ссылаться на собственные поля, поэтому её
    нельзя перемещать после начала опроса. `Pin` — обещание, что значение
    останется на месте.

## Инструменты и практика

35. **Чем `cargo check` отличается от `build`?** → [инструменты](tooling.md)
    Только разбор и проверка типов, без кодогенерации и линковки — в разы
    быстрее.

36. **Почему Rust долго компилируется?** → [инструменты](tooling.md)
    Мономорфизация плодит копии кода, LLVM их оптимизирует, единица
    компиляции — крейт целиком. Лечится разбиением на крейты, `check`,
    быстрым линкером, `sccache`.

37. **Что разрешает `unsafe`?** → [unsafe](unsafe-ffi.md)
    Пять операций (сырые указатели, `unsafe`-функции, `static mut`/`union`,
    `unsafe impl`, поля `packed`). Проверку владения и заимствования он не
    отключает.

38. **Как найти UB?** → [unsafe](unsafe-ffi.md)
    Miri (`cargo +nightly miri test`), санитайзеры, фаззинг. Тесты сами по
    себе UB не ловят.

39. **Чем doc-тест отличается от юнит- и интеграционного?** →
    [тестирование](testing.md)
    Doc-тест — пример в `///`, компилируется и запускается `cargo test`.
    Юнит-тест видит приватное, интеграционный в `tests/` — только публичный
    API.

40. **Как корректно измерять производительность?** →
    [производительность](performance.md)
    `criterion` с `black_box`, релизная сборка с символами, flamegraph.
    Цикл «измерил → изменил → измерил снова».

## Задачи на живое кодирование

Ниже — типовые задачи с указанием, что именно проверяют и в какой теме лежит
нужный материал.

**1. Топ-N слов по частоте.**
`HashMap` + entry API + сортировка. Проверяют знание
[entry](collections.md) и то, что вы не станете писать
`contains_key` с последующим `insert`.

```rust
use std::collections::HashMap;

fn top_words(text: &str, n: usize) -> Vec<(String, usize)> {
    let mut counts: HashMap<String, usize> = HashMap::new();
    for w in text.split_whitespace() {
        *counts.entry(w.to_lowercase()).or_insert(0) += 1;
    }
    let mut v: Vec<_> = counts.into_iter().collect();
    v.sort_by(|a, b| b.1.cmp(&a.1).then(a.0.cmp(&b.0)));  // по частоте, затем по слову
    v.truncate(n);
    v
}

fn main() {
    println!("{:?}", top_words("а б а в б а", 2)); // [("а", 3), ("б", 2)]
}
```

**2. Собственный итератор** и цепочка адаптеров поверх него —
см. [итераторы](closures-iterators.md).

**3. Разбор строки в структуру:** `FromStr` + свой тип ошибки через
`thiserror` — см. [ошибки](error-handling.md).

```rust
use std::str::FromStr;

#[derive(Debug, PartialEq)]
struct Point { x: i32, y: i32 }

impl FromStr for Point {
    type Err = String;

    fn from_str(s: &str) -> Result<Self, Self::Err> {
        let (a, b) = s.split_once(',').ok_or("нужен формат x,y")?;
        Ok(Point {
            x: a.trim().parse().map_err(|_| "x не число".to_string())?,
            y: b.trim().parse().map_err(|_| "y не число".to_string())?,
        })
    }
}

fn main() {
    println!("{:?}", "3, 4".parse::<Point>());   // Ok(Point { x: 3, y: 4 })
    println!("{:?}", "нет".parse::<Point>().is_err()); // true
}
```

**4. Нормализация строки без лишней аллокации** — вернуть `Cow<str>`, см.
[строки](strings.md).

**5. Обход дерева:** `enum Tree { Leaf(i32), Node(Box<Tree>, Box<Tree>) }`,
рекурсивная сумма и итеративный обход со стеком — см.
[умные указатели](smart-pointers.md).

**6. Потокобезопасный кеш** `Arc<Mutex<HashMap<K, V>>>`, затем версия с
шардированием — см. [синхронизацию](sync-primitives.md) и
[производительность](performance.md).

**7. Worker pool** на `mpsc` + `thread::spawn`, затем то же на
`rayon::par_iter` — см. [потоки](threads-send-sync.md).

**8. Параллельная загрузка N URL** на tokio с ограничением параллелизма
(`Semaphore`, `JoinSet`) и таймаутом на запрос — см. [async](async-await.md).

**9. «Почему не компилируется».** Классические три случая и идиоматичные
починки — см. [заимствование](borrowing-lifetimes.md):
две изменяемые ссылки на поля одной структуры (разбить заимствование),
возврат ссылки на локальную переменную (вернуть владение), изменение вектора
во время итерации (`retain`/`drain` или сбор индексов).

**10. Спроектировать API:** конфигурация через builder, состояния через enum,
некорректные состояния непредставимы — см.
[идиомы](idioms-api-design.md).
