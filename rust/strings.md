## Чем `String` отличается от `&str`?

**Коротко.** `String` — владеющий растущий буфер UTF-8 в куче (указатель,
длина, ёмкость). `&str` — заимствованный срез валидного UTF-8 (указатель и
длина в **байтах**), он ничем не владеет. Литерал `"abc"` имеет тип
`&'static str` и лежит в секции данных бинарника.

```rust
fn main() {
    let owned: String = String::from("привет");
    let borrowed: &str = &owned;        // deref coercion String -> &str
    let literal: &'static str = "hi";

    println!("{} {} {}", owned.len(), borrowed.len(), literal.len());
    // 12 12 2 — «привет» это 6 кодовых точек и 12 байт
}
```

`String` — это буквально `Vec<u8>` с инвариантом «внутри всегда валидный
UTF-8». Все методы, которые могут этот инвариант нарушить, либо отсутствуют,
либо `unsafe` (`as_mut_vec`).

**Подвох.** `&String` в сигнатуре — почти всегда ошибка: это лишний уровень
косвенности (указатель на структуру, внутри которой указатель на данные) и
сужение набора вызывающих — функцию с `&String` нельзя вызвать ни от литерала,
ни от среза. Правило: **принимай `&str`, возвращай `String`**.

## Почему `s[0]` не компилируется и как тогда работать с символами?

**Коротко.** Индексация одним числом запрещена, потому что байт — не символ:
в UTF-8 кодовая точка занимает от 1 до 4 байт, и `s[0]` в лучшем случае вернул
бы полсимвола. Работают срезами по байтовым границам и итераторами
`chars()`, `char_indices()`, `bytes()`.

```rust
fn main() {
    let s = "жираф";
    // println!("{}", s[0]);        // ошибка: `String` cannot be indexed by `usize`

    println!("{}", &s[0..2]);        // ж — 2 байта, граница корректна
    // println!("{}", &s[0..1]);     // паника: byte index 1 is not a char boundary

    println!("{:?}", s.chars().next());        // Some('ж')
    println!("{:?}", s.chars().nth(2));        // Some('р') — O(n), не O(1)
    for (i, c) in s.char_indices().take(2) {
        print!("{i}:{c} ");                    // 0:ж 2:и
    }
    println!();
    println!("{} {}", s.len(), s.chars().count()); // 10 5
}
```

Ключевое: `len()` — байты за O(1), `chars().count()` — кодовые точки за O(n),
и **ни то, ни другое** не равно числу символов, как их видит человек. Эмодзи
с модификатором цвета кожи, флаги, `é` в разложенной форме — это несколько
кодовых точек, образующих один графемный кластер. Кластеров в стандартной
библиотеке нет, для них берут крейт `unicode-segmentation`.

**Подвох.** Классический вопрос «переверни строку». Ответ
`s.chars().rev().collect::<String>()` корректен для большинства случаев, но
ломает графемные кластеры и комбинирующие символы — и назвать это ограничение
как раз и ждут.

## Как правильно собирать строки?

**Коротко.** `format!` — для читаемого форматирования, `push_str`/`push` — для
накопления в цикле, `String::with_capacity` — когда размер известен заранее,
`concat`/`join` — для срезов. Оператор `+` перемещает левый операнд и
принимает справа `&str`.

```rust
fn main() {
    let mut s = String::with_capacity(32);   // одна аллокация вместо нескольких
    for w in ["раз", "два", "три"] {
        s.push_str(w);
        s.push(' ');
    }
    println!("{}", s.trim_end());            // раз два три

    let a = String::from("Hello, ");
    let b = String::from("world!");
    let c = a + &b;                          // a перемещён и больше недоступен
    println!("{c}");                         // Hello, world!

    println!("{}", ["a", "b", "c"].join("-")); // a-b-c
    println!("{}", format!("{}:{}", "k", 1));  // k:1
}
```

**Подвох.** `format!` в горячем цикле — самая частая необнаруженная
аллокация: он всегда создаёт новую `String`. Если строка накапливается,
`write!` в существующий буфер (через `std::fmt::Write`) или `push_str`
дешевле.

**Глубже.** `String` растёт удвоением ёмкости, поэтому `push_str` в цикле
амортизированно O(1) — но каждая реаллокация копирует весь буфер.
`with_capacity` убирает и это, если верхняя граница известна.

## Какие ещё строковые типы есть и когда они нужны?

**Коротко.** `OsString`/`OsStr` — строки операционной системы,
`PathBuf`/`Path` — пути, `CString`/`CStr` — нуль-терминированные строки для C,
`Vec<u8>`/`&[u8]` — произвольные байты. Все они существуют потому, что не
всякий текст извне — валидный UTF-8.

| Тип (владеющий / заимствованный) | Зачем |
|---|---|
| `String` / `&str` | текст программы, гарантированный UTF-8 |
| `OsString` / `&OsStr` | аргументы, переменные окружения, имена файлов ОС |
| `PathBuf` / `&Path` | пути: разбор компонентов, расширения, склейка |
| `CString` / `&CStr` | [FFI](unsafe-ffi.md): нуль в конце, нуля внутри нет |
| `Vec<u8>` / `&[u8]` | сеть, файлы, бинарные форматы |

```rust
fn main() {
    let bytes = vec![0xD0, 0x9F, 0xD1, 0x80]; // «Пр» в UTF-8
    println!("{}", String::from_utf8(bytes.clone()).unwrap());     // Пр
    println!("{}", String::from_utf8_lossy(&[0xff, b'a']));        // <?>a
    // невалидные байты заменяются на U+FFFD, ошибки нет
}
```

**Подвох.** Почему нельзя просто везде использовать `String`: в Windows имена
файлов — это UTF-16 с возможными непарными суррогатами, в Unix — произвольные
байты без нулей. Ни то, ни другое не переводится в UTF-8 без потерь, поэтому
`std::fs` работает с `Path`, а не со `String`.

## Что такое `Cow` и когда он оправдан?

**Коротко.** `Cow<'a, str>` (clone-on-write) — перечисление «либо
заимствовано (`Borrowed(&'a str)`), либо во владении (`Owned(String)`)».
Нужно для функций «преобразуй, но не выделяй память, если менять нечего».

```rust
use std::borrow::Cow;

fn normalize(input: &str) -> Cow<'_, str> {
    if input.contains('\t') {
        Cow::Owned(input.replace('\t', "    "))   // пришлось изменить — аллоцируем
    } else {
        Cow::Borrowed(input)                      // ничего не меняли — 0 аллокаций
    }
}

fn main() {
    let clean = normalize("уже чисто");
    let dirty = normalize("есть\tтаб");
    println!("{clean}");   // уже чисто
    println!("{dirty}");   // есть    таб
    println!("{}", matches!(clean, Cow::Borrowed(_))); // true
}
```

Типичные места: нормализация и экранирование, десериализация (serde умеет
отдавать `Cow<str>`, не копируя, если данные уже в буфере),
`String::from_utf8_lossy` — она как раз возвращает `Cow`.

**Подвох.** `Cow` заражает сигнатуры временем жизни и усложняет тип ради
экономии, которая часто ничего не решает. Разумный порядок: сначала
`-> String`, а `Cow` — когда бенчмарк показал, что аллокации в этом месте
значимы.

## Как принимать «что-нибудь строковое» в обобщённой функции?

**Коротко.** `impl AsRef<str>` — если нужно только прочитать; `impl
Into<String>` — если нужно оставить у себя во владении. `&str` — если
обобщение не нужно вовсе (и это самый частый правильный ответ).

```rust
fn shout(s: impl AsRef<str>) -> String {
    s.as_ref().to_uppercase()
}

struct Config { name: String }

impl Config {
    fn new(name: impl Into<String>) -> Self {
        Config { name: name.into() } // &str -> String с копией, String -> без копии
    }
}

fn main() {
    println!("{}", shout("abc"));                 // ABC
    println!("{}", shout(String::from("xyz")));   // XYZ
    println!("{}", Config::new("prod").name);     // prod
}
```

**Глубже.** Deref coercion `&String -> &str` — работа компилятора с
конкретными типами; в обобщённом коде она **не** срабатывает: `fn f<T>(x: T)`
про `T = String` ничего не знает, поэтому и нужна явная граница `AsRef<str>`.
Разницу `AsRef` и `Borrow` разбираем в [стандартных трейтах](std-traits.md):
`Borrow` дополнительно требует согласованности `Hash`/`Eq`, поэтому именно он
позволяет искать в `HashMap<String, _>` по `&str`.
