Все примеры ниже — на двух таблицах. Обратите внимание на две «неудобные»
строки: у Веры нет ни одного заказа, а у заказа `13` не проставлен клиент.
Именно они и показывают разницу между видами соединений.

```sql
customers                 orders
┌────┬────────┐           ┌────┬─────────────┬────────┐
│ id │ name   │           │ id │ customer_id │ amount │
├────┼────────┤           ├────┼─────────────┼────────┤
│  1 │ Анна   │           │ 10 │           1 │    500 │
│  2 │ Борис  │           │ 11 │           1 │    300 │
│  3 │ Вера   │           │ 12 │           2 │    700 │
└────┴────────┘           │ 13 │        NULL │    900 │
                          └────┴─────────────┴────────┘
```

## Какие бывают виды JOIN?

**Коротко.** `INNER` — только совпадения; `LEFT`/`RIGHT` — все строки одной
стороны плюс совпадения другой; `FULL OUTER` — все строки обеих; `CROSS` —
декартово произведение.

**`INNER JOIN`** (он же просто `JOIN`) — только те строки, для которых нашлась
пара:

```sql
SELECT c.name, o.amount
FROM customers c
JOIN orders o ON o.customer_id = c.id;
-- Анна   | 500
-- Анна   | 300
-- Борис  | 700
```

Вера пропала (нет заказов), заказ `13` пропал (нет клиента).

**`LEFT JOIN`** — все строки левой таблицы; там, где пары нет, справа `NULL`:

```sql
SELECT c.name, o.amount
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id;
-- Анна   | 500
-- Анна   | 300
-- Борис  | 700
-- Вера   | NULL   <- строка сохранилась
```

**`RIGHT JOIN`** — то же зеркально. Любой `RIGHT JOIN` переписывается в `LEFT`
переменой таблиц местами, поэтому на практике его пишут редко.

**`FULL OUTER JOIN`** — все строки обеих таблиц: и Вера, и заказ `13`.

**`CROSS JOIN`** — каждая строка с каждой, без условия: 3 × 4 = 12 строк.

**Подвох.** `FULL OUTER JOIN` **не поддерживается в MySQL** (включая 8.x). Там
его эмулируют через `LEFT JOIN UNION RIGHT JOIN`. В PostgreSQL работает.

## В чём разница между условием в `ON` и в `WHERE`?

**Коротко.** Для `LEFT JOIN` — принципиальная. `ON` фильтрует **до**
соединения, `WHERE` — **после**, и тем самым превращает `LEFT JOIN` в `INNER`.

```sql
-- фильтр в ON: несовпавшие строки левой таблицы сохраняются
SELECT c.name, o.amount
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id AND o.amount > 400;
-- Анна   | 500
-- Борис  | 700
-- Вера   | NULL   <- осталась

-- фильтр в WHERE: строка с NULL не проходит условие и отсеивается
SELECT c.name, o.amount
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id
WHERE o.amount > 400;
-- Анна   | 500
-- Борис  | 700
--                 <- Веры больше нет
```

Это классический источник багов и такой же классический вопрос на собеседовании.
Причина — в [трёхзначной логике](acid-and-null.md): для Веры `o.amount` равен
`NULL`, сравнение `NULL > 400` даёт `UNKNOWN`, и `WHERE` такую строку отбрасывает.

## Как найти клиентов без заказов?

**Коротко.** `LEFT JOIN` + проверка на `NULL` по ключу правой таблицы.

```sql
SELECT c.name
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id
WHERE o.id IS NULL;
-- Вера
```

Альтернатива — `NOT EXISTS`:

```sql
SELECT name FROM customers c
WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = c.id);
-- Вера
```

**Подвох.** А вот `NOT IN` в этой задаче **молча возвращает пустой результат**:

```sql
SELECT name FROM customers
WHERE id NOT IN (SELECT customer_id FROM orders);
-- (0 строк!)
```

Потому что в подзапросе есть `NULL` (заказ `13`), а `id NOT IN (1, 2, NULL)`
разворачивается в сравнение с `NULL`, которое даёт `UNKNOWN` — и ни одна строка
не проходит. Правило: **с потенциально NULL-колонками используйте `NOT EXISTS`,
а не `NOT IN`**.

## Что такое SELF JOIN?

**Коротко.** Соединение таблицы с самой собой — нужно для иерархий и сравнения
строк между собой. Обязательны псевдонимы, чтобы различать две «копии».

```sql
emp: (1, Директор, NULL), (2, Пётр, 1), (3, Ольга, 2)

SELECT e.name AS сотрудник, m.name AS руководитель
FROM emp e
LEFT JOIN emp m ON e.mgr = m.id;
-- Директор | NULL
-- Пётр     | Директор
-- Ольга    | Пётр
```

`LEFT JOIN` здесь важен: с `INNER JOIN` директор без руководителя выпал бы.

## Что ещё спрашивают про JOIN

- **Дублирование строк.** Если справа несколько совпадений, строка слева
  повторится столько раз, сколько нашлось пар. Анна в примерах выше встречается
  дважды — это не ошибка, а нормальное поведение.
- **`CROSS JOIN` против `JOIN` без условия.** Это одно и то же; `CROSS JOIN`
  просто явно сообщает, что декартово произведение — намерение, а не забытый `ON`.
- **`USING`.** Сокращение для случая, когда столбцы называются одинаково:
  `JOIN orders USING (customer_id)`.
- **`NATURAL JOIN`** соединяет по всем одноимённым столбцам автоматически. В
  проде его избегают: добавили столбец с совпадающим именем — запрос молча
  поменял смысл.
