## Что такое первичный ключ?

**Коротко.** Столбец или набор столбцов, однозначно идентифицирующий строку.
`NULL` не допускается, значение уникально, на таблицу он один.

```sql
CREATE TABLE users (
    id   bigserial PRIMARY KEY,
    email text NOT NULL
);

-- составной первичный ключ
CREATE TABLE order_items (
    order_id   int,
    product_id int,
    qty        int NOT NULL,
    PRIMARY KEY (order_id, product_id)
);
```

Смежная терминология, которую часто спрашивают следом:

- **Потенциальный (candidate) ключ** — любой минимальный набор столбцов,
  однозначно определяющий строку. Один из них выбирают первичным.
- **Естественный (natural) ключ** — из предметной области: ИНН, email.
- **Суррогатный (surrogate) ключ** — искусственный: автоинкремент или UUID.

**Подвох.** «Какой ключ выбрать — естественный или суррогатный?» Практика
склоняется к суррогатному: естественные ключи имеют свойство меняться (человек
сменил email) и утекать в бизнес-логику, а каскадное обновление ключа по всем
ссылающимся таблицам дорого.

## Чем `UNIQUE` отличается от `PRIMARY KEY`?

**Коротко.** `UNIQUE` тоже гарантирует уникальность, но их может быть несколько
на таблицу, и он допускает `NULL`.

```sql
CREATE TABLE users (
    id    bigserial PRIMARY KEY,
    email text UNIQUE,          -- уникален, но может быть NULL
    phone text UNIQUE
);
```

**Подвох.** Сколько `NULL` пускает `UNIQUE` — зависит от СУБД, и это любимый
вопрос:

- **PostgreSQL, MySQL, Oracle** (стандартное поведение) — `NULL` не равен другому
  `NULL`, поэтому таких строк можно вставить **сколько угодно**.
- **MS SQL Server** — исключение: трактует `NULL` в уникальном индексе как
  дубликаты и допускает только **одно** значение.

С PostgreSQL 15 поведение стало управляемым:

```sql
-- PostgreSQL 15+: запретить более одного NULL
CREATE TABLE t (col int UNIQUE NULLS NOT DISTINCT);
```

## Что такое внешний ключ и что делать при удалении родителя?

**Коротко.** `FOREIGN KEY` обеспечивает ссылочную целостность: нельзя сослаться
на несуществующую строку и нельзя осиротить дочерние строки.

Поведение при удалении или изменении родителя задаётся явно:

```sql
CREATE TABLE orders (
    id          bigserial PRIMARY KEY,
    customer_id bigint REFERENCES customers(id) ON DELETE CASCADE
);
```

| Действие | Что происходит при удалении родителя |
|---|---|
| `NO ACTION` (по умолчанию) | Ошибка — но проверка может быть отложена |
| `RESTRICT` | Ошибка сразу, отложить нельзя |
| `CASCADE` | Дочерние строки удаляются следом |
| `SET NULL` | В дочерних строках ключ обнуляется |
| `SET DEFAULT` | Подставляется значение по умолчанию |

**Подвох.** `ON DELETE CASCADE` удобен и опасен: удаление одной строки может
молча снести половину базы по цепочке. В продовой схеме его обычно ставят только
там, где дочерняя запись не имеет смысла без родителя.

**Глубже.** В PostgreSQL ограничение можно объявить `DEFERRABLE INITIALLY
DEFERRED` — тогда проверка выполнится не построчно, а в момент `COMMIT`. Это
единственный способ вставить взаимно ссылающиеся строки в одной транзакции.

## Какие бывают ограничения?

| Ограничение | Что гарантирует |
|---|---|
| `NOT NULL` | Значение обязательно |
| `UNIQUE` | Нет повторов |
| `PRIMARY KEY` | `NOT NULL` + `UNIQUE` |
| `FOREIGN KEY` | Ссылка ведёт на существующую строку |
| `CHECK` | Выражение истинно |
| `DEFAULT` | Значение по умолчанию (формально не ограничение) |
| `EXCLUDE` | Расширение Postgres: никакие две строки не «конфликтуют» по оператору |

```sql
CREATE TABLE products (
    id    bigserial PRIMARY KEY,
    price numeric(12, 2) CHECK (price > 0),
    sku   text NOT NULL UNIQUE
);
```

**Подвох.** `CHECK` пропускает строку не только при `TRUE`, но и при `UNKNOWN` —
то есть `CHECK (price > 0)` **не защитит** от `NULL` в `price`. Нужен ещё явный
`NOT NULL`. Разобрано в разделе [ACID и NULL](acid-and-null.md).

## Что такое целостность данных?

Это обобщение трёх видов целостности, которые мы уже разобрали выше: PK
обеспечивает целостность сущностей, FK — ссылочную, а `CHECK` и правильные типы
столбцов — доменную. Три уровня, о которых стоит сказать явно:

- **Целостность сущностей (entity integrity)** — у каждой строки есть уникальный
  первичный ключ, не равный `NULL`.
- **Ссылочная целостность (referential integrity)** — внешние ключи ведут на
  существующие строки.
- **Доменная целостность (domain integrity)** — значения соответствуют типу и
  ограничениям столбца.
