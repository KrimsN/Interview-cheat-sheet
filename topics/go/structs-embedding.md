# Go: структуры и встраивание

[🏠 Карта тем по Go](README.md)

## Что нужно знать

- **Структура — значение**: присваивание и передача копируют все поля.
  Копия структуры, содержащей слайс или карту, разделяет с оригиналом их данные
  (shallow copy) — типичный источник багов.
- **Литералы**: всегда предпочитайте именованные поля `T{Name: "x"}` —
  позиционный литерал ломается при добавлении поля в структуру.
- **Теги полей** (`json:"name,omitempty"`, `db:"..."`, `validate:"..."`) —
  строки, читаемые через рефлексию. Работают только для экспортируемых полей.
- **Встраивание (embedding)** — анонимное поле: `type Server struct { *log.Logger }`.
  Методы и поля встроенного типа **промоутируются** наружу, вызов
  `s.Printf(...)` работает. Это композиция, а **не наследование**: нет
  виртуальных вызовов, встроенный тип ничего не знает о внешнем, переопределение
  метода не меняет поведение методов встроенного типа (нет полиморфизма
  «сверху вниз»).
- **Конфликты имён** при встраивании нескольких типов разрешаются по глубине;
  на одинаковой глубине неоднозначность — ошибка компиляции при обращении,
  но не при объявлении.
- **Встраивание интерфейса в структуру** — идиома для частичных реализаций и
  моков: структура автоматически удовлетворяет интерфейсу, а невызванные
  методы паникуют на `nil`.
- **Пустая структура `struct{}`** занимает 0 байт: множества `map[K]struct{}`,
  сигнальные каналы `chan struct{}`, методы-приёмники без состояния.
- **Выравнивание полей**: порядок полей влияет на размер структуры из-за
  padding. `unsafe.Sizeof` и `fieldalignment` из `go vet`/`staticcheck` помогают.
  Оптимизация уместна только в горячих структурах, создаваемых миллионами.
- **Сравнимость**: структуры сравнимы `==`, если все поля сравнимы; иначе —
  только `reflect.DeepEqual` / `go-cmp`.
- **Конструкторы**: в Go нет конструкторов, идиома — `func NewX(...) (*X, error)`.
  Если нулевое значение полезно — конструктор не нужен вовсе.
- **Функциональные опции** (`func(*Config)`) — идиоматичный способ задать
  необязательные параметры вместо перегрузки и десятка конструкторов.
- **`sync.Mutex`/`sync.WaitGroup` внутри структуры** делают её некопируемой —
  `go vet` ловит копирование через `copylocks`. Идиома: методы на указателе.

## Ссылки

- [Effective Go: Embedding](https://go.dev/doc/effective_go#embedding) — канонический разбор встраивания и того, чем оно не является.
- [JSON and Go](https://go.dev/blog/json) — теги полей, маршалинг структур и правила экспортируемости.
- [Go Spec: Struct types](https://go.dev/ref/spec#Struct_types) — правила промоутирования полей и разрешения конфликтов имён.
- [Functional options for friendly APIs — Dave Cheney](https://dave.cheney.net/2014/10/17/functional-options-for-friendly-apis) — классическая статья про паттерн опций.
- [Uber Go Style Guide](https://github.com/uber-go/guide/blob/master/style.md) — практические правила по структурам, нулевым значениям и мьютексам внутри типов.
