# Go: обработка ошибок

[🏠 Карта тем по Go](README.md)

## Что нужно знать

- **`error` — обычный интерфейс** с единственным методом `Error() string`.
  Ошибки — значения, их возвращают, а не бросают. Идиома: ошибка — последнее
  возвращаемое значение, проверяется сразу: `if err != nil { return ... }`.
- **Никогда не игнорируйте ошибку через `_`** без комментария; `errcheck` и
  линтеры это ловят.
- **Sentinel-ошибки**: `var ErrNotFound = errors.New("not found")` — сравнение
  через `errors.Is`. Они становятся частью публичного API пакета, поэтому
  вводить их стоит осознанно (`io.EOF`, `sql.ErrNoRows`).
- **Свои типы ошибок**: структура с полями + метод `Error()`, извлекается через
  `errors.As`. Помните ловушку с `nil`-указателем внутри интерфейса — см.
  [интерфейсы](interfaces.md).
- **Оборачивание (Go 1.13+)**: `fmt.Errorf("get user %d: %w", id, err)` —
  глагол `%w` сохраняет цепочку. `errors.Unwrap`, `errors.Is` (сравнение по
  значению вглубь цепочки), `errors.As` (поиск по типу вглубь цепочки).
  `errors.Join` (Go 1.20) объединяет несколько ошибок, `%w` можно указать
  несколько раз.
- **Правило контекста**: при оборачивании добавляйте информацию, которой ещё
  нет у вызывающего, и **не начинайте** сообщение с заглавной буквы и не
  заканчивайте точкой (`go vet`: `ST1005`). Не логируйте и не возвращайте
  ошибку одновременно — выберите одно.
- **`panic` — для программных ошибок**, а не для ожидаемых сбоев: обращение по
  `nil`-указателю, выход за границы, невозможное состояние. `recover` работает
  только внутри `defer` и обычно уместен на границе (HTTP-мидлварь, обработчик
  задачи в воркере), чтобы не уронить весь процесс.
- **Что recover не спасёт**: `fatal error: concurrent map writes`, дедлок всех
  горутин, переполнение стека, OOM — это фатальные ошибки рантайма, а не паники.
- **Паника в горутине роняет весь процесс**, если внутри самой горутины нет
  `recover` — популярный вопрос.
- **Структурное логирование ошибок** — `log/slog` (Go 1.21+), поля вместо
  форматированных строк.
- **Внешние библиотеки**: `pkg/errors` (исторический, дал stack traces до 1.13),
  `github.com/cockroachdb/errors`. Знать, что стандартная библиотека
  **не хранит стектрейс** — частый уточняющий вопрос.
