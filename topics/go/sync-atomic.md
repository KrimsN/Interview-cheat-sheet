# Go: пакет sync, atomic и модель памяти

[🏠 Карта тем по Go](README.md)

## Что нужно знать

- **`sync.Mutex`** — не рекурсивный (повторный `Lock` в той же горутине =
  дедлок), не привязан к горутине (разблокировать может другая), нулевое
  значение готово к работе. Идиома: `mu` объявляется рядом с защищаемым полем,
  `defer mu.Unlock()` сразу после `Lock()`.
- **`sync.RWMutex`** — много читателей или один писатель. Выигрывает только при
  реально долгих чтениях; ожидающий писатель блокирует новых читателей
  (защита от голодания). На коротких критических секциях обычный `Mutex`
  быстрее.
- **Копирование структуры с мьютексом ломает синхронизацию** — `go vet`
  (`copylocks`) это ловит. Отсюда методы на указателе.
- **`sync.WaitGroup`**: `Add` **до** запуска горутины, `defer wg.Done()`
  внутри, `wg.Wait()` снаружи. `Add` внутри горутины — гонка. Go 1.25 добавил
  `wg.Go(func())`, снимающий этот класс ошибок.
- **`sync.Once`** — ленивая инициализация, `Do` гарантирует ровно один вызов и
  дожидается его завершения. Есть `OnceValue`/`OnceFunc` (Go 1.21+).
- **`sync.Map`** — не «быстрая map», а специализация: выигрывает при кэше,
  который пишется редко и читается часто, либо когда горутины работают с
  непересекающимися ключами. В остальных случаях `map` + `RWMutex` быстрее и
  типобезопаснее.
- **`sync.Pool`** — переиспользование временных объектов ради снижения нагрузки
  на GC (буферы). Содержимое может быть очищено в любой момент между циклами
  GC; не для пула соединений и не для объектов со смыслом.
- **`sync.Cond`** — редко нужен, но про него спрашивают: `Wait`/`Signal`/
  `Broadcast` поверх `Locker`; почти всегда заменяется каналом.
- **`sync/atomic`**: `atomic.Int64`, `atomic.Pointer[T]`, `CompareAndSwap`,
  `Add`, `Load`, `Store` (типизированные типы с Go 1.19 — предпочтительнее
  функций на указателях). Атомарность ≠ логическая корректность:
  read-modify-write из двух атомарных операций всё ещё гонка.
- **Модель памяти Go**: гарантии happens-before дают запуск горутины, обмен по
  каналу (отправка happens-before завершения соответствующего приёма; закрытие
  happens-before приёма нуля), `Mutex.Unlock` → следующий `Lock`, `Once.Do`,
  атомарные операции (sequentially consistent). Без синхронизации компилятор и
  процессор вправе переупорядочивать — «переменная-флаг без atomic» это гонка,
  даже если «на практике работает».
- **Race detector**: `go test -race`, `go run -race`. Ловит только те гонки,
  что реально случились в прогоне; замедляет в 5–10 раз и увеличивает память,
  но в CI обязателен.
- **Дедлоки**: рантайм умеет обнаружить только полный дедлок всех горутин
  (`fatal error: all goroutines are asleep`). Частичный дедлок не
  диагностируется — только `pprof goroutine`.
