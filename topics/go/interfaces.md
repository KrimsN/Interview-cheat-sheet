# Go: интерфейсы

[🏠 Карта тем по Go](README.md)

## Что нужно знать

- **Неявная реализация (structural typing)**: тип удовлетворяет интерфейсу,
  если у него есть нужные методы; ключевого слова `implements` нет. Следствие —
  интерфейс объявляют **на стороне потребителя**, а не рядом с реализацией.
- **Маленькие интерфейсы лучше**: `io.Reader`, `io.Writer`, `error`,
  `fmt.Stringer`, `sort.Interface`. «The bigger the interface, the weaker the
  abstraction» — одна из Go Proverbs.
- **Внутреннее устройство**: интерфейсное значение — пара `(тип, значение)`.
  Для непустого интерфейса это `iface{tab *itab, data unsafe.Pointer}`,
  для `interface{}` — `eface{_type, data}`. Отсюда:
  - **`nil`-интерфейс ≠ интерфейс с `nil` внутри.** Классическая ловушка:
    функция возвращает `error`, а внутри кладёт в неё `*MyErr(nil)` — проверка
    `if err != nil` даёт **true**, потому что тип не пустой. Никогда не
    возвращайте конкретный тип ошибки в переменную конкретного типа, а потом
    её же в интерфейс.
  - вызов метода через интерфейс — косвенный (через itab), инлайнинг обычно
    невозможен, и укладывание значения в интерфейс часто вызывает аллокацию
    (escape to heap).
- **Type assertion и type switch**: `v, ok := i.(T)` (без `ok` — паника),
  `switch v := i.(type) { case ... }`. Утверждение к интерфейсу проверяет
  наличие методов в рантайме — так делают опциональные расширения
  (`io.ReaderFrom`, `http.Flusher`).
- **Пустой интерфейс `interface{}` / `any`** (алиас с Go 1.18) — «любой тип»,
  но не «динамическая типизация»: чтобы что-то сделать со значением, нужен
  type switch, рефлексия или дженерики. Часто дженерики — правильный ответ.
- **Композиция интерфейсов**: `io.ReadWriter` = встраивание `Reader` + `Writer`.
- **Проверка на этапе компиляции**: `var _ Iface = (*Impl)(nil)` — идиома,
  чтобы поймать несоответствие сразу.
- **Интерфейсы с параметрами типа** (Go 1.18+) могут содержать не только
  методы, но и множества типов (`~int | ~string`) — тогда они годны только
  как ограничения в дженериках.
- **Рефлексия** (`reflect`) — «три закона рефлексии»: от интерфейса к
  `reflect.Value`, обратно, и изменять можно только адресуемое значение.
  Знать цену: медленно, ломает статические гарантии; в проде — только для
  сериализации, ORM, DI-контейнеров.
