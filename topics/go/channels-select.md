# Go: каналы и select

[🏠 Карта тем по Go](README.md)

## Что нужно знать

- **«Не общайтесь через разделяемую память — делите память через общение»** —
  главный лозунг, но в стандартной библиотеке мьютексы используются не реже
  каналов. Канал — для передачи владения и координации, мьютекс — для защиты
  состояния.
- **Небуферизованный канал синхронный**: отправка блокируется, пока кто-то не
  начнёт приём, — это точка рандеву и одновременно гарантия happens-before.
  **Буферизованный** блокирует только на полном буфере.
- **Таблица поведения** (обязательный вопрос):
  | Операция | nil-канал | закрытый канал |
  |---|---|---|
  | чтение | блокируется навсегда | сразу отдаёт zero value, `ok == false` |
  | запись | блокируется навсегда | **паника** |
  | `close` | паника | **паника** |
- **`v, ok := <-ch`** отличает «пришло значение» от «канал закрыт».
  `for v := range ch` завершается при закрытии.
- **Закрывает всегда отправитель** (или единственный владелец). Закрытие — это
  broadcast «данных больше не будет», а не «освободить ресурс»; канал не надо
  закрывать ради GC.
- **Несколько отправителей** — закрывать нельзя без внешней координации:
  идиома с `done`-каналом/контекстом либо `sync.WaitGroup` и закрытие в
  отдельной горутине после `wg.Wait()`.
- **`select`**: ждёт первый готовый case; при нескольких готовых выбирает
  **случайно** (защита от голодания). `default` делает операцию неблокирующей.
  `select {}` без case — вечная блокировка. Читаемый `nil`-канал в case
  «выключает» этот case — идиома для динамического отключения ветки.
- **Таймауты и отмена**: `case <-time.After(d)` (аллоцирует таймер на каждый
  вызов — в цикле используйте `time.NewTimer`/`Ticker` с `Stop`),
  `case <-ctx.Done()`.
- **Направленные типы** `chan<- T` и `<-chan T` в сигнатурах — документируют
  намерение и ловят ошибки на компиляции.
- **Каналы и производительность**: канал внутри — это мьютекс, кольцевой
  буфер и очереди ожидающих горутин. Для счётчика канал в разы дороже
  `atomic`. Не используйте канал там, где хватает мьютекса.
- **Типовые ловушки**: запись в канал, который никто не читает (утечка
  горутины); `close` дважды; ожидание N значений из канала, куда пишут N-1;
  «сигнальный» канал `chan struct{}` и почему `close(done)` лучше отправки —
  его «видят» все ожидающие.
