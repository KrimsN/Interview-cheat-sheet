# Go: идиомы, стиль и архитектура проекта

[🏠 Карта тем по Go](README.md)

## Что нужно знать

- **Форматирование не обсуждается**: `gofmt` — единый стиль, отступы табами,
  импорты сгруппированы (`goimports`). Комментарии к экспортируемым сущностям
  начинаются с имени: `// Server handles ...`.
- **Ключевые идиомы**:
  - «Принимай интерфейсы, возвращай структуры»;
  - «Интерфейс объявляет потребитель»;
  - «The zero value should be useful»;
  - ранний возврат вместо вложенности (`if err != nil { return }`),
    «happy path» слева у края;
  - «Don't panic» — паника не средство контроля потока;
  - «A little copying is better than a little dependency»;
  - «Clear is better than clever».
- **Именование**: короткие имена в узкой области (`i`, `r`, `w`), длинные — в
  широкой; `MixedCaps`, не `snake_case`; аббревиатуры в одном регистре
  (`userID`, `HTTPServer`); интерфейсы с одним методом — `-er` (`Reader`).
- **Структура проекта**: `cmd/<binary>/main.go`, `internal/` для приватного
  кода, доменные пакеты по смыслу (`billing`, `user`), а **не** по слоям
  (`models`, `utils`, `helpers` — антипаттерн). Пакет `util` — запах.
- **Архитектурные подходы**: слоистая, гексагональная / ports & adapters,
  clean architecture. В Go они реализуются буквально через маленькие
  интерфейсы и внедрение зависимостей вручную (`main` как composition root);
  DI-контейнеры (`wire`, `fx`) — по желанию. См. языконезависимые темы:
  [архитектура](../../fundamentals/architecture.md) и
  [внедрение зависимостей](../../fundamentals/dependency-injection.md).
- **Конфигурация**: переменные окружения (12-factor), `flag`, `envconfig`,
  `viper`; валидация конфигурации на старте и fail-fast.
- **Логирование и наблюдаемость**: структурные логи (`log/slog`), метрики
  Prometheus, трассировка OpenTelemetry, health/readiness-эндпоинты.
- **Обработка ошибок в слоях**: доменные ошибки в домене, маппинг в HTTP-коды
  на границе, никаких `panic` в бизнес-логике.
- **Go-специфичные code smells**: голые `interface{}`/`any` в сигнатурах,
  «геттеры-сеттеры на всё», гигантские интерфейсы, пакеты-«боги»,
  глобальное изменяемое состояние, `init()` с побочными эффектами, каналы
  там, где нужен мьютекс, преждевременные горутины.
- **Совместимость**: обещание Go 1 о обратной совместимости; правила
  расширения API без ломающих изменений (добавляйте методы к структурам, не
  к интерфейсам; используйте функциональные опции).

## Ссылки

- [Effective Go](https://go.dev/doc/effective_go) — базовый документ об идиомах и стиле.
- [Go Code Review Comments](https://go.dev/wiki/CodeReviewComments) — список замечаний, которые чаще всего пишут на ревью Go-кода.
- [Google Go Style Guide](https://google.github.io/styleguide/go/) — развёрнутый стиль-гайд с обоснованиями решений.
- [Uber Go Style Guide](https://github.com/uber-go/guide/blob/master/style.md) — практические правила от большой продакшен-кодовой базы.
- [Practical Go — Dave Cheney](https://dave.cheney.net/practical-go/presentations/qcon-china.html) — реальные советы по проектированию пакетов, API и конкурентности.
- [Go Proverbs](https://go-proverbs.github.io/) — короткие формулировки философии языка, удобно цитировать на интервью.
- [Organizing a Go module](https://go.dev/doc/modules/layout) — официальная позиция по раскладке каталогов.
