# Rust: владение, перемещение и Drop

[🏠 Карта тем по Rust](README.md)

## Что нужно знать

- **Три правила владения**: у каждого значения ровно один владелец; владелец
  один в каждый момент времени; когда владелец выходит из области видимости,
  значение уничтожается. Это статическая замена и сборщику мусора, и ручному
  `free`.
- **Move-семантика по умолчанию**: присваивание или передача в функцию
  **перемещает** значение, исходная переменная становится недоступной
  («use of moved value», `E0382`). Копируются только типы, реализующие `Copy`
  (скаляры, неизменяемые ссылки, кортежи из `Copy`-типов) — их побитовая копия
  безопасна.
- **`Copy` vs `Clone`**: `Copy` — неявная побитовая копия, маркерный трейт без
  методов; `Clone` — явное, потенциально дорогое `.clone()`. Тип с `Drop`
  не может быть `Copy` — иначе деструктор вызвался бы дважды.
- **RAII и `Drop`**: освобождение ресурса привязано к концу жизни значения.
  `Drop::drop` вызывается автоматически, поля уничтожаются в порядке
  объявления, локальные переменные — в обратном порядке. Вручную `drop` у
  трейта звать нельзя — только `drop(x)`, который просто забирает владение.
  `std::mem::forget` и цикл из `Rc` безопасны с точки зрения языка: утечка
  памяти не считается нарушением safety.
- **Стек и куча**: `Vec`, `String`, `Box` — владельцы, у которых метаданные
  (указатель, длина, ёмкость) лежат на стеке, а данные в куче. Move — это
  копия метаданных, не данных: перемещение `Vec` не копирует элементы.
- **Частичное перемещение** (partial move): можно вынести поле из структуры,
  после чего структура целиком недоступна, а остальные поля — да. Из типов с
  `Drop` частичное перемещение запрещено.
- **Возврат владения** — обычный способ отдать значение вызывающему. Когда
  владение забирать не хочется, берут ссылку — см.
  [заимствование](borrowing-lifetimes.md).
- **Почему нет GC**: детерминированное освобождение даёт предсказуемые
  задержки и позволяет владеть не только памятью, но и файлами, сокетами,
  блокировками — тем же механизмом.
- **Типичные вопросы**: что произойдёт при двойном освобождении (компилятор
  не даст); зачем `clone`, если он дорогой (осознанная явная цена); чем move
  в Rust отличается от move в C++ (в Rust исходная переменная становится
  статически недоступной, а не остаётся в «moved-from» состоянии с вызовом
  деструктора).
