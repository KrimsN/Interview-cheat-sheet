# Rust: дженерики, мономорфизация и dyn

[🏠 Карта тем по Rust](README.md)

## Что нужно знать

- **Дженерики проверяются на месте определения**, а не при подстановке: если
  внутри обобщённой функции вызывается метод, он должен быть заявлен в
  границах (`T: Trait`). Это отличие от шаблонов C++, где ошибки всплывают
  при инстанцировании.
- **Мономорфизация**: компилятор генерирует отдельную копию кода под каждый
  конкретный тип. Плюс — инлайнинг и нулевая цена абстракции; минус —
  раздувание бинарника и время компиляции (реальная причина, почему Rust
  собирается долго).
- **`impl Trait`**: в аргументе — сахар для обобщённого параметра;
  в возвращаемом типе — «конкретный, но скрытый тип» (нужно для замыканий и
  футур, которые нельзя назвать). В трейтах — RPITIT, стабилизировано в 1.75.
- **Статическая vs динамическая диспетчеризация**: `dyn Trait` даёт один
  экземпляр кода, гетерогенные коллекции (`Vec<Box<dyn Shape>>`) и меньший
  бинарник ценой косвенного вызова и отсутствия инлайнинга. Практическое
  правило: дженерики по умолчанию, `dyn` — когда нужна гетерогенность,
  плагины или борьба с раздуванием кода.
- **Границы**: `T: Clone + Send + 'static`, `where`-клаузы, границы на
  ассоциированных типах (`I: Iterator<Item = u8>`), негативных границ нет.
- **Обобщения над временами жизни и константами**: `fn f<'a, const N: usize>`;
  const generics позволяют, например, `struct Matrix<const R: usize, const C: usize>`.
- **GAT (generic associated types)**, стабилизированы в 1.65 — ассоциированные
  типы с параметрами; практическая мотивация — лендинг-итераторы и
  абстракции над async.
- **Turbofish** `collect::<Vec<_>>()` — способ подсказать компилятору тип,
  когда вывод неоднозначен.
- **Специализации нет** (только на nightly): «оптимизирую обобщённый код для
  конкретного типа» решается через отдельные трейты или внутренние приёмы
  вроде `TypeId`.
- **Zero-cost abstraction на практике**: итератор с цепочкой `map`/`filter`
  компилируется в тот же цикл, что и ручной; проверять — через ассемблер
  (Compiler Explorer) или бенчмарки, а не верить на слово.
- **Что спрашивают**: чем `impl Trait` в аргументе отличается от `dyn Trait`;
  сколько кода сгенерируется для функции с тремя типами-параметрами; как
  уменьшить раздувание (внутренняя не-обобщённая функция + тонкая обобщённая
  обёртка).
