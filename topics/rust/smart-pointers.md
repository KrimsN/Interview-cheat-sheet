# Rust: умные указатели и внутренняя изменяемость

[🏠 Карта тем по Rust](README.md)

## Что нужно знать

- **`Box<T>`** — единственный владелец значения в куче. Нужен для рекурсивных
  типов (список, дерево, AST), для больших значений и для трейт-объектов
  (`Box<dyn Trait>`). Накладных расходов сверх одной аллокации нет.
- **`Rc<T>`** — разделяемое владение с подсчётом ссылок, **однопоточное**
  (счётчик неатомарный, тип не `Send`). `Arc<T>` — то же с атомарным
  счётчиком, для многопоточности. Разница по цене: атомарные операции против
  обычного инкремента, поэтому `Arc` не берут «на всякий случай».
- **`Rc`/`Arc` дают только неизменяемый доступ**; чтобы менять данные, их
  комбинируют с `RefCell` (однопоточно) или `Mutex`/`RwLock`
  (многопоточно): `Rc<RefCell<T>>`, `Arc<Mutex<T>>` — два самых узнаваемых
  сочетания в языке.
- **Циклы `Rc` — утечка памяти**: счётчик никогда не дойдёт до нуля.
  Разрывают через `Weak<T>` (не влияет на счётчик сильных ссылок,
  `upgrade()` возвращает `Option<Rc<T>>`). Классическая пара «родитель
  владеет детьми через `Rc`, дети ссылаются на родителя через `Weak`».
- **Внутренняя изменяемость** — изменение через `&T`, когда компилятор
  статически проверить не может:
  - `Cell<T>` — только копирование значения внутрь и наружу, без ссылок,
    без накладных расходов;
  - `RefCell<T>` — динамическая проверка правил заимствования: `borrow()` и
    `borrow_mut()` **паникуют** при нарушении, то есть проверка переезжает из
    компиляции в рантайм;
  - `OnceCell`/`OnceLock`/`LazyLock` — однократная ленивая инициализация
    (`LazyLock` стабилен с 1.80 и закрывает нишу `lazy_static`/`once_cell`).
- **`UnsafeCell<T>`** — примитив, на котором построены все перечисленные;
  единственный легальный способ получить `&mut` из `&`.
- **Трейты умных указателей**: `Deref`/`DerefMut` (даёт автоматическое
  разыменование и `&String -> &str`), `Drop`, `AsRef`, `Borrow`. Deref
  coercion — причина, по которой методы `str` вызываются у `String`, а методы
  `[T]` у `Vec<T>`.
- **`Cow<'a, T>`** — заимствование с ленивым клонированием при записи.
- **Что спрашивают**: чем `Box` отличается от `Rc`; почему `Rc` не `Send`;
  что произойдёт при двойном `borrow_mut` у `RefCell` (паника
  `already borrowed`); как сделать двусвязный список (ответ: `Rc<RefCell<>>` +
  `Weak`, либо арена с индексами, либо `unsafe` — и почему это учебный пример
  сложности).
