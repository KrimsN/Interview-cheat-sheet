# Rust: обработка ошибок

[🏠 Карта тем по Rust](README.md)

## Что нужно знать

- **Две категории сбоев**: восстановимые — `Result<T, E>`, невосстановимые —
  `panic!`. Исключений в языке нет, ошибка — обычное возвращаемое значение,
  которое нельзя молча проигнорировать (`#[must_use]` на `Result`).
- **Оператор `?`**: разворачивает `Ok`/`Some` или делает ранний возврат,
  применяя `From` к типу ошибки. Работает в функциях, возвращающих `Result`,
  `Option` или совместимый тип; в `main` тоже — если она возвращает
  `Result<(), E>`.
- **Свой тип ошибки** — enum вариантов + реализация `Display` и
  `std::error::Error` (+ `source()` для цепочки). Обычно генерируется
  `thiserror` в библиотеках; в приложениях чаще `anyhow::Error`
  (стёртый тип + контекст + backtrace через `.context(...)`).
- **Правило экосистемы**: библиотека — конкретный enum ошибок (вызывающий
  должен уметь разобрать причину), приложение — стёртый тип и контекст.
  Ровно тот же вопрос задают и в Go про sentinel-ошибки против типов.
- **`Box<dyn Error>`** — вариант без внешних крейтов: годится для прототипов и
  `main`, но теряет типизацию.
- **Паника**: `panic!`, `unwrap`, `expect`, выход за границы среза,
  переполнение в debug, `RefCell` с двойным заимствованием, деление на ноль.
  По умолчанию раскручивает стек (`unwind`) и вызывает деструкторы; профиль
  `panic = "abort"` в `Cargo.toml` убирает раскрутку и уменьшает размер
  бинарника.
- **Ловля паники**: `std::panic::catch_unwind` существует (нужен для границ
  FFI и тестовых раннеров), но это не механизм обработки ошибок; паника в
  потоке роняет только этот поток, `JoinHandle::join` вернёт `Err`.
- **Отравление (poisoning)**: паника внутри `Mutex` помечает его как
  отравленный — см. [синхронизацию](sync-primitives.md).
- **Когда паника уместна**: нарушен инвариант программы, невозможное
  состояние, ошибка программиста; когда нет — ввод пользователя, сеть, файлы,
  парсинг.
- **Полезные приёмы**: `ok_or_else` для перехода `Option -> Result`,
  `map_err` для приведения типа, `collect::<Result<Vec<_>, _>>()` для
  сворачивания итератора результатов в один `Result`,
  `unwrap_or_default`.
- **Подвох на интервью**: чем `?` отличается от `try!` (устаревший макрос);
  почему `unwrap` в библиотечном коде — плохая практика; что делает `expect`
  с точки зрения сообщений и `RUST_BACKTRACE`.
