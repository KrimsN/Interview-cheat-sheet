# Rust: идиомы и проектирование API

[🏠 Карта тем по Rust](README.md)

## Что нужно знать

- **«Сделай некорректные состояния непредставимыми»** — главный
  проектный принцип: enum вместо булевых флагов, newtype вместо голых
  `String`/`u64`, `Option` вместо «пустой строки как отсутствия», отдельный
  тип для проверенных данных (`Email`, `NonEmptyVec`).
- **Newtype** решает три задачи сразу: типобезопасность, обход orphan rule и
  сокрытие внутреннего представления. Стоимость в рантайме нулевая.
- **Typestate**: состояние объекта в типе (`Request<Draft>` →
  `Request<Sent>`), некорректный переход не компилируется. Спрашивают как
  «чем Rust отличается от языка с рантайм-проверками».
- **Builder** — идиоматичная замена именованным и опциональным аргументам,
  которых в языке нет: `Foo::builder().a(1).b(2).build()`; часто
  генерируется `derive_builder`/`bon`, а `#[non_exhaustive]` на структуре
  оставляет место для новых полей без слома API.
- **Правила сигнатур**: принимать `&str`/`&[T]`/`impl AsRef<Path>`,
  возвращать владеющие типы; не принимать `&Vec<T>` и `&String`; не
  возвращать `Box<dyn Trait>` там, где хватит `impl Trait`.
- **RAII-обёртки для всего**, а не пары «открой/закрой»: guard-объекты для
  блокировок, транзакций, временных файлов, таймеров.
- **Модульность**: приватность по умолчанию, `pub use` как фасад,
  `#[non_exhaustive]` для enum ошибок, чтобы добавление варианта не ломало
  совместимость.
- **Идиомы кода**: `if let ... else`/`let ... else` вместо вложенных
  `match`, комбинаторы `Option`/`Result` вместо ручных проверок, итераторы
  вместо индексных циклов, `impl Default` вместо конструктора без
  аргументов, `From` вместо `new_from_x`.
- **Именование**: `new`, `with_capacity`, `into_x` (потребляет), `to_x`
  (копирует, дорогое), `as_x` (дешёвое заимствование), `is_x`/`has_x` для
  предикатов, `try_x` для `Result`. Соглашение закреплено в API Guidelines.
- **Что считается code smell**: обилие `clone()` и `unwrap()` вместо
  проектирования, `Rc<RefCell<...>>` там, где хватило бы владения,
  «объектно-ориентированный» код с наследованием через трейты, преждевременный
  `unsafe`, глобальное состояние через `static mut`.
- **Документация как часть API**: `///` с примером, который проверяется
  `cargo test`, `#[must_use]` на типах, которые нельзя игнорировать,
  `#![deny(missing_docs)]` в библиотеке.
