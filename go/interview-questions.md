## Язык и типы

1. **Чем массив отличается от слайса? Что произойдёт при `append` сверх
   `cap`?** → [массивы и слайсы](arrays-slices.md)
   Массив — значение фиксированной длины, копируется целиком при присваивании.
   Слайс — заголовок (указатель, длина, вместимость) поверх массива;
   `append` сверх `cap` аллоцирует новый, больший массив и копирует данные —
   старый слайс перестаёт быть связан с новым.

2. **Что вернёт `len("привет")` и почему?** → [строки и руны](strings-runes.md)
   12, а не 6 — строка в Go это байты UTF-8, а не руны; кириллическая буква
   занимает 2 байта. Для длины в рунах нужен `utf8.RuneCountInString` или
   `len([]rune(s))`.

3. **Почему запись в `nil`-карту паникует, а чтение — нет?** → [карты](maps.md)
   Чтение из `nil`-карты — это просто чтение из пустой карты (возвращает
   нулевое значение), а запись требует существующей внутренней структуры
   хеш-таблицы, которой у `nil`-карты нет — отсюда `panic: assignment to
   entry in nil map`.

4. **В чём разница между `type A B` и `type A = B`?** → [типы](types-constants.md)
   `type A B` объявляет новый именованный тип с базовым типом `B` — методы
   `B` не наследуются, нужно явное приведение. `type A = B` — псевдоним,
   `A` и `B` буквально один и тот же тип везде, включая совместимость по
   интерфейсам.

5. **Value receiver или pointer receiver — как выбрать и как это влияет на
   удовлетворение интерфейса?** → [методы](methods-receivers.md)
   Pointer receiver — когда метод меняет состояние или структура большая;
   value receiver — для маленьких неизменяемых типов. Набор методов
   value-типа не включает методы с pointer receiver, поэтому не каждое
   значение такого типа удовлетворяет интерфейсу — только адресуемое.

6. **Почему `err != nil` истинно, хотя вернули `nil`-указатель?**
   → [интерфейсы](interfaces.md)
   Интерфейсное значение — это пара (тип, значение); если вернуть типизированный
   `nil`-указатель как `error`, тип в паре не пустой, поэтому интерфейс в
   целом не равен `nil`, даже когда сам указатель — `nil`.

7. **Что печатает `defer` с аргументом-переменной, изменённой после?**
   → [defer/panic/recover](defer-panic-recover.md)
   Аргументы `defer` вычисляются в момент вызова `defer`, а не в момент
   фактического выполнения — печатается значение на момент объявления
   отложенного вызова, не финальное.

8. **Зачем дженерики, если есть `any`, и когда они не нужны?**
   → [дженерики](generics.md)
   `any` теряет типобезопасность и требует приведения типов в рантайме;
   дженерики сохраняют проверку компилятором и убирают дублирование кода
   под разные типы. Не нужны, когда достаточно интерфейса с методами —
   дженерики решают задачу «одна и та же логика для разных типов данных»,
   а не «разное поведение для разных типов».

## Конкурентность

9. **Чем горутина отличается от потока ОС? Что такое GMP и `GOMAXPROCS`?**
   → [горутины и планировщик](goroutines-scheduler.md)
   Горутина — лёгкий поток уровня рантайма Go, стартовый стек — единицы
   килобайт (растёт по требованию), в отличие от потока ОС с фиксированным
   мегабайтным стеком. GMP — модель планировщика (Goroutine, Machine-поток
   ОС, Processor-логический процессор), `GOMAXPROCS` ограничивает число P,
   выполняющих Go-код параллельно.

10. **Что произойдёт при чтении/записи/закрытии закрытого и `nil`-канала?**
    → [каналы и select](channels-select.md)
    Чтение из закрытого канала — сразу нулевое значение и `ok == false`, без
    блокировки. Запись в закрытый канал — паника. Повторное закрытие
    закрытого канала — паника. Любая операция (кроме `select` с `default`)
    над `nil`-каналом блокируется навсегда.

11. **Кто должен закрывать канал и почему?**
    Только отправитель (или один явно назначенный владелец), никогда
    получатель — закрытие с двух сторон или получателем неизбежно ведёт либо
    к панике «close of closed channel», либо к рассинхронизации о том, кто
    ещё жив.

12. **Как ограничить число одновременно работающих горутин?**
    → [паттерны конкурентности](concurrency-patterns.md)
    Worker pool с фиксированным числом горутин, читающих из общего канала
    задач, либо семафор на буферизованном канале (`chan struct{}` заданной
    ёмкости), либо `golang.org/x/sync/errgroup` с `SetLimit`.

13. **Что такое утечка горутин и как её найти?**
    Горутина, которая заблокирована навсегда (ждёт канал, в который никто не
    напишет/из которого никто не прочитает) и потому никогда не завершится —
    рантайм её не соберёт, память и стек утекают. Ищут через
    `runtime.NumGoroutine()` в динамике, `pprof` goroutine-профиль, и
    `go.uber.org/goleak` в тестах.

14. **Канал или мьютекс — как выбрать? Чем `sync.Map` отличается от `map` +
    `RWMutex`?** → [sync и atomic](sync-atomic.md)
    Канал — для передачи владения данными или сигнализации между
    горутинами («don't communicate by sharing memory, share memory by
    communicating»); мьютекс — для защиты общего состояния на месте.
    `sync.Map` оптимизирована под конкретный паттерн доступа (много чтений,
    редкие записи разных ключей разными горутинами) и в общем случае
    медленнее и менее удобна по API, чем обычная `map` под `RWMutex`.

15. **Как работает `context` и почему `cancel` нужно вызывать всегда?**
    → [context](context.md)
    `context.Context` несёт дедлайн/отмену и переносимые значения по дереву
    вызовов; `cancel`, возвращаемый `WithCancel`/`WithTimeout`/`WithDeadline`,
    нужно вызывать через `defer` даже при успешном завершении — иначе
    ресурсы, связанные с контекстом (таймер, горутина-наблюдатель), утекают
    до срабатывания дедлайна или сборки родителя.

16. **Что такое data race и как её обнаружить?**
    Одновременный доступ к одной и той же памяти минимум из двух горутин,
    хотя бы один из которых — запись, без синхронизации — неопределённое
    поведение независимо от того, «повезло» ли на конкретном прогоне.
    Обнаруживается флагом `-race` (`go test -race`, `go run -race`),
    который инструментирует обращения к памяти в рантайме.

## Рантайм и производительность

17. **Где размещается переменная — на стеке или в куче? Кто решает?**
    → [память и GC](memory-gc.md)
    Решает компилятор через escape-анализ: если время жизни переменной
    доказуемо не выходит за пределы функции, она остаётся на стеке; если
    берётся адрес и он «убегает» наружу (возврат указателя, запись в
    глобальную структуру, передача в интерфейс), переменная уходит в кучу.

18. **Как устроен сборщик мусора и что делают `GOGC` и `GOMEMLIMIT`?**
    Конкурентный трёхцветный mark-and-sweep с очень короткими паузами
    stop-the-world. `GOGC` задаёт, во сколько раз куча может вырасти
    относительно предыдущего сбора мусора, прежде чем запустится следующий
    (по умолчанию 100%); `GOMEMLIMIT` — жёсткий потолок общей памяти,
    независимо от `GOGC`, полезен в контейнерах с ограничением по памяти.

19. **Как найти, почему сервис ест память / тормозит?**
    → [инструменты и профилирование](tooling-profiling.md)
    `net/http/pprof` подключается в проде за флагом, снимает heap/CPU/
    goroutine-профили без остановки сервиса; дальше — `go tool pprof` с
    `top`/`list`/`web` для локализации проблемного кода.

## Практика

20. **Как устроен HTTP-сервер в Go, зачем таймауты и graceful shutdown?**
    → [HTTP-сервисы](http-servers.md)

21. **Как писать табличные тесты и зачем `-race` в CI?**
    → [тестирование](testing.md)
    Табличный тест — срез структур `{name, input, want}`, прогоняемых одним
    циклом через `t.Run(tt.name, ...)` для независимых сообщений об ошибке
    по каждому кейсу. `-race` в CI ловит гонки данных на реальных прогонах,
    которые не всегда воспроизводятся вручную.

22. **Как работают модули и MVS?** → [модули и пакеты](modules-packages.md)
    `go.mod` фиксирует минимально необходимые версии зависимостей; MVS
    (Minimal Version Selection) при сборке берёт для каждого модуля
    максимум из версий, запрошенных где-либо в графе зависимостей — не
    последнюю доступную, а минимальную версию, достаточную, чтобы
    удовлетворить все требования.

### Живое кодирование (часто просят написать)

- Worker pool с ограничением параллелизма и сбором ошибок.
- Слить N каналов в один (fan-in) с корректным закрытием.
- Реализовать таймаут вокруг функции через `select`.
- Потокобезопасный кэш с TTL (`map` + `RWMutex` + фоновая очистка).
- Реализовать `Stack`/`Set` на дженериках.
- Перевернуть строку с корректной обработкой Unicode.
- Найти дубликаты в слайсе за O(n) через `map[K]struct{}`.
- Пайплайн: генератор → трансформер → сборщик, с отменой по контексту.
- LRU-кэш (`container/list` + карта).
- Ограничитель скорости (token bucket) вручную на `time.Ticker`.
