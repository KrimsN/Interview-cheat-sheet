## Почему в Go нет исключений, наследования и перегрузки операторов?

**Коротко.** Это осознанный выбор дизайна в пользу простоты: явные ошибки как
значения вместо `try/catch`, композиция вместо наследования классов,
единственный способ форматирования кода (`gofmt`). Цель — маленькая
спецификация, которую можно прочитать за вечер, и код, который одинаково
выглядит у всех.

Авторы языка (Роб Пайк, Кен Томпсон, Роберт Гризмер) делали Go для больших
командных кодовых баз в Google, где скорость компиляции, читаемость чужого
кода и предсказуемость важнее лаконичности и выразительной мощи. Отсюда прямые
следствия:

- ошибки — обычные возвращаемые значения (`error`), а не отдельный канал
  управления потоком, как исключения;
- вместо наследования — встраивание (`embedding`) структур и интерфейсов,
  композиция вместо иерархии;
- один канонический стиль форматирования, навязанный инструментом `gofmt`, а
  не соглашением команды;
- почти 10 лет в языке не было generics — сначала искали минимальную
  конструкцию, не усложняющую компилятор и не плодящую перегрузки (появились
  в Go 1.18).

**Подвох.** «Раз в Go нет исключений — как обрабатывать по-настоящему
аварийные ситуации?» Для них есть `panic`/`recover`, но это не замена
`error`: `panic` — для программных ошибок (обращение по нулевому указателю,
выход за границы слайса) и ситуаций, после которых процесс не может
продолжать работу, а не штатный контроль потока. Идиоматичный код почти
никогда не вызывает `panic` в библиотечном коде и всегда возвращает `error`
из функций, которые могут закономерно завершиться неудачно.

## Что такое zero value и как устроена идиома «полезный нулевой объект»?

**Коротко.** Любая переменная в Go при объявлении без инициализации получает
нулевое значение своего типа — `0` для чисел, `""` для строк, `false` для
`bool`, `nil` для указателей, слайсов, карт, каналов, функций и интерфейсов.
Это не «мусор», а гарантированное, воспроизводимое состояние.

Отсюда родилась идиома «полезный нулевой объект» (useful zero value):
некоторые типы стандартной библиотеки спроектированы так, чтобы нулевое
значение сразу было рабочим, без явного конструктора.

```go
var buf bytes.Buffer
buf.WriteString("hello")
fmt.Println(buf.String()) // hello — буфер не требовал New()

var mu sync.Mutex
mu.Lock()
mu.Unlock() // мьютекс тоже готов к использованию сразу
```

Для структур это значит, что `var s MyStruct` — валидное, безопасное
значение: каждое поле получает свой zero value рекурсивно.

**Подвох.** Zero value для слайса и карты выглядит одинаково («пусто»), но
ведёт себя по-разному: с `nil`-слайсом можно работать почти как с обычным
(`append`, `len`, `range` не паникуют), а запись в `nil`-карту — паника в
рантайме. Это разбирается подробнее в [Массивах и слайсах](arrays-slices.md)
и в [Картах](maps.md).

## Что такое `iota` и как с его помощью объявляют перечисления?

**Коротко.** `iota` — счётчик, который растёт от `0` на каждой новой строке
внутри блока `const (...)` и сбрасывается в `0` на каждом новом блоке. В Go
нет отдельного ключевого слова `enum` — идиоматичная замена строится на
`iota` поверх именованного типа.

```go
type Weekday int

const (
    Sunday Weekday = iota // 0
    Monday                // 1
    Tuesday                // 2
    Wednesday              // 3
)
```

`iota` — это просто число, участвующее в произвольном выражении, поэтому им
удобно задавать степени двойки для битовых флагов или единиц измерения:

```go
type ByteSize float64

const (
    _          = iota             // пропускаем нулевое значение
    KB ByteSize = 1 << (10 * iota) // 1 << 10
    MB                              // 1 << 20
    GB                              // 1 << 30
)
```

**Подвох.** Значения `iota`-перечисления — это `int`-подобный тип без
проверки диапазона на этапе компиляции: ничто не мешает передать в функцию,
принимающую `Weekday`, значение `Weekday(99)`, которого нет среди констант.
Настоящей защиты, как `enum class` в C++ или `Enum` в Python, в Go нет; в
проде для валидации либо пишут `String()` со switch и default-веткой, либо
проверяют значение явно.

**Глубже.** Чтобы такое перечисление красиво печаталось, для типа определяют
метод `String() string` — тогда `fmt.Println(Monday)` выведет `Monday`, а не
`1`, потому что пакет `fmt` проверяет реализацию интерфейса `Stringer`.

## Как в Go устроен контроль видимости — где `public`, где `private`?

**Коротко.** Видимость идентификатора определяется первой буквой его имени:
с заглавной — экспортируется и видно за пределами пакета, со строчной —
видно только внутри пакета. Отдельных ключевых слов `public`/`private`/
`protected` в языке нет.

```go
package models

type User struct {
    Name  string // экспортируется
    email string // видно только внутри пакета models
}

func NewUser(name string) *User { return &User{Name: name} } // экспортируется
func normalize(s string) string { return s }                  // не экспортируется
```

Правило единое для всего: типов, функций, методов, полей структур, констант
и переменных пакетного уровня.

**Подвох.** Регистр контролирует видимость только на уровне **пакета**, а не
файла — все файлы одного пакета (даже в одной директории с разными именами)
делят один и тот же набор «приватных» идентификаторов без каких-либо
дополнительных `import`. Ловушка для новичков — думать, что приватность
работает как в Java, на уровне файла или класса.

## Какие есть формы `for` и что изменилось с переменной цикла в Go 1.22?

**Коротко.** В Go один цикл — `for`, но четыре синтаксические формы: с тремя
частями (init; condition; post), с одним условием (аналог `while`), без
условия (бесконечный) и `for range` по коллекциям. С Go 1.22 переменные цикла
`for range` (и трёх-частного `for`, если используется старый стиль объявления
в заголовке) создаются заново на каждой итерации, а не переиспользуются.

```go
for i := 0; i < 3; i++ { /* классическая форма */ }

n := 0
for n < 3 { n++ } // аналог while

for { break } // бесконечный, выход через break

for i, v := range []string{"a", "b"} { _ = i; _ = v }
```

До Go 1.22 переменная цикла была **одна на весь цикл** и просто
перезаписывалась на каждой итерации. Из-за этого запуск горутины внутри
цикла с захватом переменной по имени был классической ловушкой: к моменту
реального выполнения горутины переменная могла уже содержать последнее
значение.

```go
// go 1.22+: у каждой итерации своя переменная v — гонки за значение нет
var wg sync.WaitGroup
results := make([]int, 0, 3)
var mu sync.Mutex

for _, v := range []int{1, 2, 3} {
    wg.Add(1)
    go func() {
        defer wg.Done()
        mu.Lock()
        results = append(results, v)
        mu.Unlock()
    }()
}
wg.Wait()
// results содержит {1, 2, 3} в произвольном порядке, но без дублей и потерь
```

**Подвох.** «Значит, на Go 1.22+ так писать всегда безопасно?» Само поведение
переменной цикла — да, но поведение зависит не от версии компилятора, а от
директивы `go 1.XX` в `go.mod`: если модуль объявляет более старую версию
языка, `go vet`/компилятор применяют старую семантику. Это тот редкий случай,
когда обновление патч-версии тулчейна не меняет поведение кода, а меняет
именно язык, указанный в `go.mod`.

## Как Go передаёт аргументы в функции — по значению или по ссылке?

**Коротко.** Всегда по значению: копируется весь аргумент, каким бы он ни
был — числом, структурой или дескриптором слайса/карты/канала. Иллюзия
«ссылочной семантики» для слайсов и карт возникает потому, что копируется
небольшой дескриптор, а данные, на которые он указывает, общие.

```go
func changeList(lst []int) {
    lst[0] = 99 // мутация общих данных — видна снаружи
}

func changeInt(n int) {
    n++ // n — локальная копия, снаружи не видно
}

a := []int{1, 2, 3}
b := 10
changeList(a)
changeInt(b)
// a -> [99 2 3]
// b -> 10
```

С этим связаны ещё две особенности функций в Go:

- **Множественный возврат** — идиоматичный способ вернуть `(значение,
  error)` без исключений и без `out`-параметров.
- **Именованные результаты** — объявляются в сигнатуре и доступны как
  обычные переменные; `return` без аргументов («naked return») возвращает их
  текущие значения. Удобны в маленьких функциях, но в длинных — вредят
  читаемости, потому что значение результата приходится искать по всему телу.

```go
func divmod(a, b int) (q, r int, err error) {
    if b == 0 {
        err = errors.New("division by zero")
        return // вернёт q=0, r=0 и err
    }
    q, r = a/b, a%b
    return
}
```

- **Variadic-параметры** `...T` принимают произвольное число аргументов как
  слайс внутри функции, а существующий слайс разворачивается в такие
  аргументы через `slice...`:

```go
func sum(nums ...int) int {
    total := 0
    for _, n := range nums {
        total += n
    }
    return total
}

nums := []int{1, 2, 3, 4}
sum(nums...) // 10, а не sum([]int{...}) одним аргументом-слайсом
```

**Подвох.** Указатели в Go есть, но арифметики указателей нет — `p + 1` не
скомпилируется. `new(T)` выделяет память под `T` и возвращает `*T`,
заполненный zero value, но на практике почти всегда используют литерал
`&T{...}`, потому что он одновременно выделяет память и инициализирует поля.
Разыменование для доступа к полям и вызова методов происходит неявно:
`p.Field` работает и для `T`, и для `*T`, компилятор сам вставляет `(*p).Field`.
