## Что вернёт `len(s)` для строки — количество байтов или символов?

**Коротко.** Строка в Go — это неизменяемый срез байтов в кодировке UTF-8, а
не последовательность символов. `len(s)` всегда возвращает **число байтов**.
Число «символов» (точнее, кодовых точек Unicode — рун) нужно считать отдельно
через `utf8.RuneCountInString`.

```go
s := "привет"
fmt.Println(len(s))                   // 12 — 6 кириллических букв по 2 байта
fmt.Println(utf8.RuneCountInString(s)) // 6
```

Индексирование `s[i]` тоже работает по байтам и возвращает `byte`, а не
символ: `s[0]` для `"привет"` — это первый байт двухбайтовой кодировки буквы
«п», а не сама буква.

```go
fmt.Printf("%T %v\n", s[0], s[0]) // uint8 208
```

Чтобы пройтись именно по символам (рунам), используют `for range` по
строке — он декодирует UTF-8 сам и отдаёт байтовый индекс начала руны вместе
с самой руной:

```go
for i, r := range s {
    fmt.Printf("%d:%c ", i, r)
}
// 0:п 2:р 4:и 6:в 8:е 10:т — индексы растут не на 1, а на длину руны в байтах
```

**Подвох.** Это самый частый практический вопрос по строкам на собеседовании:
«почему `s[i]` и `range s` дают разные вещи». Ответ — они оперируют разными
единицами: `s[i]` всегда байт по фиксированному смещению `O(1)`, `range`
всегда руна с декодированием UTF-8 на лету. Прямой индексации «i-й символ»
в Go в принципе не существует — только через промежуточное `[]rune(s)`.

## Как правильно развернуть строку задом наперёд?

**Коротко.** Переворачивать байты строки нельзя — сломается многобайтовая
кодировка. Разворачивают срез рун (`[]rune`), а не байтов, и это тоже
классическая задача на собеседовании, потому что почти всегда её решают
неверно с первого раза.

```go
func reverseRunes(s string) string {
    r := []rune(s)
    for i, j := 0, len(r)-1; i < j; i, j = i+1, j-1 {
        r[i], r[j] = r[j], r[i]
    }
    return string(r)
}

reverseRunes("hello")   // olleh
reverseRunes("привет")  // тевирп
```

**Подвох.** Руна — это кодовая точка Unicode (`int32`), а не «символ» в
бытовом понимании. То, что человек видит как один символ, может состоять из
нескольких рун — например, emoji с модификатором тона кожи или буква с
комбинирующим диакритическим знаком. Разворот «по рунам» для такого текста
всё равно сломает визуальный порядок: комбинирующий знак окажется привязан
не к той букве. Правильный ответ на собеседовании — сказать, что `[]rune`
решает проблему многобайтовости, но не проблему grapheme cluster'ов; для
последнего нужны специализированные Unicode-библиотеки.

**Глубже.** Конверсии `[]byte(s)` и `[]rune(s)` всегда копируют данные — это
аллокация, а не бесплатный вид на те же байты, потому что строка неизменяема,
а слайс — нет. Компилятор оптимизирует несколько частых паттернов без
дополнительной аллокации: `for i, r := range []byte(s)` не любит, а вот
`for range []rune(s)` — типичный случай, где нельзя избежать копии; при этом
`m[string(byteSlice)]` для поиска в карте компилятор умеет выполнять без
лишней аллокации, распознавая этот конкретный паттерн.

## Как правильно конкатенировать строки в цикле?

**Коротко.** `s += x` в цикле — плохая идея: строки неизменяемы, поэтому
каждая конкатенация выделяет новый массив байтов и копирует туда старое
содержимое целиком, что даёт квадратичную сложность по суммарному объёму.
Идиоматичная замена — `strings.Builder` (или `bytes.Buffer` для байтов), с
`Grow()` заранее, если размер результата известен или хотя бы оценивается.

```go
var b strings.Builder
b.Grow(64) // преаллокация, если размер известен заранее
for i := 0; i < 3; i++ {
    b.WriteString("go")
}
fmt.Println(b.String()) // gogogo
```

Из полезных функций пакета `strings` отдельно стоит знать `strings.Cut` —
современную идиому вместо `strings.SplitN(s, sep, 2)` для разбиения строки
на «до разделителя» и «после»:

```go
before, after, found := strings.Cut("key=value", "=")
fmt.Println(before, after, found) // key value true
```

Для сравнения строк без учёта регистра есть `strings.EqualFold` — она
корректнее ручного `strings.ToLower(a) == strings.ToLower(b)`, потому что не
аллоцирует промежуточные строки и правильнее работает с некоторыми
Unicode-раскладками регистра.

**Подвох.** `strings.Builder` нельзя копировать после первой записи — при
попытке скопировать структуру, в которую уже писали, `go vet` и рантайм
поймают это через встроенную защиту (`noCopy`), потому что копия будет
делить внутренний буфер способом, который легко приводит к порче данных.
Передавать `Builder` между функциями нужно по указателю.

## Как форматный вывод `%v` работает с собственными типами?

**Коротко.** Если тип реализует интерфейс `fmt.Stringer` (метод
`String() string`), глаголы `%v` и `%s` вызывают именно его. `%#v` печатает
Go-синтаксис значения (полезно для отладки структур), `%T` — имя типа,
`%q` — оборачивает строку в кавычки с экранированием, а `%w` работает только
внутри `fmt.Errorf` и оборачивает ошибку так, чтобы её потом можно было
достать через `errors.Unwrap`/`errors.Is`/`errors.As`.

```go
type Point struct{ X, Y int }

func (p Point) String() string {
    return fmt.Sprintf("(%d, %d)", p.X, p.Y)
}

p := Point{1, 2}
fmt.Printf("%v\n", p)  // (1, 2)  — вызван String()
fmt.Printf("%#v\n", p) // main.Point{X:1, Y:2} — Stringer здесь не используется
fmt.Printf("%T\n", p)  // main.Point

err := fmt.Errorf("read failed: %w", fmt.Errorf("eof"))
fmt.Println(err) // read failed: eof
```

**Подвох.** Если внутри `String()` печатать сам получатель через `%v`
(`fmt.Sprintf("%v", p)` вместо обращения к полям), получится бесконечная
рекурсия: `fmt` снова увидит, что у типа есть `String()`, и вызовет его же.
Правильно — обращаться к полям напрямую или явно приводить к вспомогательному
типу без метода `String()` перед форматированием.
